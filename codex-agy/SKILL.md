# 直接调用 AGY

## 从设计到验收

开发委托按以下顺序执行。每一步产出可核对的结果后，再进入下一步。

1. **Codex 完成详细开发设计。** 核实现有行为，写出可直接指导实施的设计文件，按任务写清模块职责、接口和数据契约、主流程和边界条件、状态与事务边界、失败处理及验收用例。
2. **AGY 用有额度的旗舰模型、Medium 推理强度做只读可行性评审。** 在委托中引用设计文件，要求 AGY 对照现有代码给出结论、依据、风险和阻塞项。需要终端工具时，先用同一工作目录、模式和会话权限验证一条已获授权的只读命令。缺少实质结论时留在评审阶段，由 Codex 排障并续接评审。CLI 的 `SUCCESS` 只代表调用状态。
3. **Codex 复核评审，双方对同一版设计达成一致。** Codex 用代码、约束和必要的验证核对 AGY 的发现。设计确有问题时，修订后请 AGY 复评。若异议来自分析前提或判断有误，向 AGY 说明证据和理由，再请它复核。续接讨论，直到 Codex 和 AGY 都明确认可同一版设计可实施，并处理完影响实施的分歧。未达成一致时保留在评审阶段，向用户说明仍需解决的问题。
4. **向用户汇报定稿并等待明确确认。** 说明最终设计、改动范围、关键决策、风险与验收方式，并附设计文件路径。确认前只做设计、只读评审和必要排障。收到用户对该版设计的明确确认后，才启动 `accept-edits`。如果实施中需要实质改变设计或范围，受影响部分重新评审并交用户确认。
5. **Codex 派发，AGY 负责人组织实施。** Codex 在用户确认后，用旗舰模型 Medium 新开负责人会话，交付定稿、范围和验收条件。负责人在设计内拆分步骤、安排中档 High 执行者、协调依赖、集成和自检，集中向 Codex 交付结果。改变设计或范围时交回 Codex。实施受阻时由 Codex 排障并恢复委托。
6. **Codex 独立验收。** AGY 交回自检结果后，Codex 对照设计检查整个项目受影响的链路、实际差异和测试内容，并独立执行必要的构建、测试或运行检查。集中列出有依据的问题交回 AGY 修复，再核对本轮差异并复验，直到达到验收条件再交付。

## 控制上下文和往返

- **按需读取。** Codex 用 `rg` 定位入口、契约和风险相关实现，再读取必要片段。已核实且未变化的内容沿用结论。新的证据或依赖关系需要时再扩展调查范围。
- **约束日志输出。** 完整构建日志和 AGY 原始输出保存到任务目录。进入 Codex 上下文的优先是退出码、摘要、用量、拒绝项和失败片段，需要时再读原文件。AGY 报告引用文件路径，源码变更通过 Git 差异审查。
- **等待实际进展。** 预计耗时较长的 AGY 或构建调用，首次等待使用工具支持的较长时限。仍在运行时，常规等待每次 30–60 秒，同一进程只保留一个等待链。空输出或状态未变时继续等待。发现超时、报错或长时间没有进展后再定向查日志。状态汇报遵循宿主要求。
- **集中验收与修复。** AGY 写入期间等待其完成交付单元和自检，再集中检查。把本轮已确认问题和失败证据一次交回 AGY，自主修复后复验。修复后重点检查本轮变化、受影响调用方及相关回归项。新发现的风险再扩大检查。
- **按阶段交接。** 设计评审与分歧讨论续接评审会话。用户确认设计后，以定稿文件、验收条件和必要约束交给新的 AGY 实施会话。同一交付单元的修复优先续接。独立交付单元开新会话。上下文已混入大量旧日志时，先核实前次运行结束并保留交接摘要，再从当前 Git 状态新开会话。
- **复用有效配置。** 同一环境中已验证的模型列表、路径和权限探测结果可以复用。切换阶段时查额度，权限配置或环境变化、出现拒绝时再探测。Codex 与 AGY 避免同时写同一工作区。负责人并行派发写任务时，使用已授权的隔离工作树，或核实文件修改范围互不重叠。共享契约和集成改动按依赖顺序执行。

## 派发给 AGY 负责人

Codex 负责实际 Shell 调用、选择模型和传入本轮已验证的权限设置。负责人使用普通 `agy -p` 会话，以委托提示明确职责。委托文件由 Codex 按任务准备，包含最终设计路径、用户已确认的范围、交付单元及依赖、验收命令、执行者模型要求、允许改动范围和必须上报的问题。负责人可自主细分编码步骤，并负责内部修复和整体验证。

首次采用内部子 Agent 时，先核对 `agy agents`、CLI 帮助和当前工具能力，验证 headless 下可调用执行者，并从实际调用证据核对执行者的模型和推理档位。`--model` 只明确设置负责人会话的模型。内部执行者的独立选型必须通过当前支持的子 Agent 配置实现。若能力或档位无法满足，负责人向 Codex 报告，由 Codex 调整可用调用方式，完成验证后再派发开发。[AGY 子 Agent 文档](https://antigravity.google/docs/subagents)

```bash
agy --project '<项目 ID>' --model '<旗舰 Medium 模型 ID>' --mode accept-edits --output-format json \
  -p '你是本次 AGY 实施负责人。读取 <委托文件绝对路径> 和其中引用的用户已确认设计。按设计拆分实施任务，使用已验证的中档 High 子 Agent 配置分派编码和测试，协调依赖与写入范围，完成集成、自检和局部修复。遇到设计冲突或能力限制先报告 Codex。等内部任务结束并核对实际验证结果后，集中返回改动摘要、测试证据路径和未完成项。'
```

同一交付单元的纠偏和返工，Codex 用负责人的 `conversation_id` 续接，提交集中问题清单。日常实现细节由负责人内部协调，需要 Codex 决策的冲突和最终验收结果再回传。

## 先查本机帮助

当前 Codex 对话首次使用 AGY 时，先运行 `command -v agy` 和 `agy --help`，再选择调用方式。使用不熟悉的子命令时，先运行 `agy <子命令> --help`。遇到参数报错、CLI 升级或发现文档与本机行为有差异时，重新查对应帮助后再重试。需要交互式斜杠命令时，另外核对该命令是否支持当前的交互或 headless 模式。

## 委托前检查模型和额度

在选模型前由 Codex 运行以下命令。进入下一阶段前刷新额度，并把实际选用的模型和对应模型组的剩余额度简要告诉用户。

```bash
agy models
agy -p '/usage'
```

查询额度时保留 CLI 的斜杠命令处理，避免给 `/usage` 加 `--disable-slash-commands`。

> 先查看 AGY 当前可用模型和剩余额度。可行性评审和 AGY 实施负责人使用有额度的旗舰模型，推理强度 Medium。内部编码、测试和修复执行者使用有额度的中档模型（如 Flash），推理强度 High。

按 CLI 实际返回的模型 ID 和额度选型，检查适用的短时、周度及模型专属额度。优先使用列表中已经包含推理档位的模型 ID。若使用基础模型 ID，则用 `--effort medium` 或 `--effort high` 显式指定档位。首选组合不可用时，选同档且支持所需推理强度的模型并说明。查询失败时报告额度未知。没有符合条件的组合时向用户说明限制。按阶段传入模型参数，续接会话时也显式选型。[AGY 模型与推理参数](https://antigravity.google/docs/cli/reference/) · [AGY 模型额度](https://antigravity.google/docs/cli/commands/usage)

## 命令

以当前 Codex 对话的工作区目录为准，用它的绝对路径作为 Shell 调用的工作目录。若 Codex 当前就在 Git 工作树中，AGY 使用同一个工作树。比较路径时解析符号链接，例如用 `pwd -P` 确认实际目录。

Codex 项目中的新委托归档到同名 AGY 项目。以 Codex 中显示的项目名称为准，分别确认名称和实际工作区。复用已有项目时，核对项目配置包含目标目录且范围适合本次委托，再用 `--project '<项目 ID>'` 启动。遇到同名但目录不匹配的项目，先解决归属再委托。

没有同名项目时，创建与 Codex 项目同名、绑定目标工作区的 AGY 项目。本机 CLI 的 `--new-project` 默认用启动目录的名称建项目，只有目录名与 Codex 项目名一致时才直接使用该参数，否则在 AGY 项目界面指定名称和目录。当前本机版本可从 `~/.gemini/config/projects/<项目 ID>.json` 核对 `name`、`id` 和 `projectResources.resources[]` 中的 `folderUri` 或 `gitFolder.folderUri`。如果当前对话没有 Codex 项目，或用户明确要求使用默认 CLI 项目，可省略 `--project`。[AGY 项目文档](https://antigravity.google/docs/projects?tab=cli)

```bash
agy --project '<项目 ID>' --model '<旗舰 Medium 模型 ID>' --mode plan --output-format json -p '评估这项方案的可行性，指出风险和待决问题。只读分析。'
agy --project '<项目 ID>' --model '<旗舰 Medium 模型 ID>' --mode accept-edits --output-format json -p '按已批准的方案文件实施，执行约定的测试并报告结果。'
```

将示例提示替换为实际目标、已确定的方案、允许范围和验收条件。较长的内容或关键方案放在 AGY 可读取的项目文件中，在提示里给出路径。可用自然语言要求 AGY 说明改动、测试结果和待决问题。

## 读取结果与续接

`--output-format json` 返回 CLI 原生 JSON。读取 stdout 的 `response`，结合进程退出码、`status`、`error`、出现时的 `denied_actions` 和 stderr 判断实际执行情况。即使 CLI 返回成功，也要以实际改动与验证结果为准。无需续接时也可直接读默认文本输出。

按阶段交接规则选择新会话或续接。续接时使用上一轮 JSON 的 `conversation_id`，核对工作区和项目归属。确认目标是当前目录最近使用的会话时，也可用 `--continue`（`-c`）。每次 `agy -p` 都启动新进程。有交错委托或归属不确定时，用 `--conversation` 精确续接。

```bash
agy --conversation '<conversation_id>' --model '<旗舰 Medium 模型 ID>' --mode accept-edits --output-format json \
  -p '按更新后的方案文件和下面的验收要求继续。'

agy --continue --model '<旗舰 Medium 模型 ID>' --mode plan --output-format json \
  -p '继续只读分析，补充上一轮的待决问题。'
```

核对返回的会话 ID。独立委托按上面的项目归档规则开启新会话，省略 `--conversation` 和 `--continue`。旧会话不可用或属于其他工作区时，先核对已发生的改动，再把当前方案和剩余工作交给从当前工作区启动的新会话。续接时仍应引用关键方案文件，以应对上下文压缩。[AGY 会话工作区](https://antigravity.google/docs/cli/conversations) · [AGY Headless 文档](https://antigravity.google/docs/cli/headless#continue-a-conversation)

## 权限

生产代码、测试代码及实现所需的项目配置由 AGY 编写和修改。Codex 负责设计、委托、排障和验收。若 headless 拒绝 `RunCommand`，结合 `denied_actions`、stderr、委托目标和 Git 差异，查清被拦的动作、它是否必要，以及已完成的改动。根据原因在原授权范围内处理：

- 文件查阅或编辑可用 AGY 的文件工具完成时，调整提示并续接原委托。
- Git 检查、构建或测试等命令可由 Codex 按现有权限执行时，主动执行并把结果带回原 AGY 会话，让 AGY 继续实施或修复。若 Codex 的权限规则也拒绝该动作，遵循该规则。
- AGY 必须亲自运行某条已获授权的命令时，先核对本机支持的会话权限配置，再用 `--settings` 仅放行本轮所需的命令。需要新增授权时，说明具体命令、用途和影响，继续推进无需该权限的部分。

重试时从已确认的 Git 状态继续，按可独立验证的范围拆分剩余工作。确实无法继续时，报告具体阻塞和待完成范围，由 AGY 在阻塞解除后继续实施。

### 验证 headless 委托能执行

1. 需要 AGY 运行终端命令时，先按本机 CLI 支持的方式配置会话权限，只授权本轮需要的动作。在 MQ 任务中，经验证可用的组合是 `--sandbox` 加上会话设置 `enableTerminalSandbox: true` 和 `toolPermission: "proceed-in-sandbox"`，同时按任务配置具体的 `permissions.allow` 和 `permissions.deny`，包括禁止 `unsandboxed(*)`。该模式会允许沙箱内的命令，仅在现有授权覆盖这种运行方式时使用。只授权个别命令时，用经核实的具体允许规则或由 Codex 代跑。
2. 先用相同的设置委托一个小探测，例如让 AGY 实际运行 `git status --short` 并返回结果。核对工具执行证据和 Git 基线。正式评审或实施调用使用已验证的相应设置。已有会话用 `--conversation` 续接时再次传入 `--settings`。
3. 超时或出现拒绝后，先核对 Git 差异和实际测试输出。权限问题恢复后按原阶段续接。已写入的改动按实际状态交给 AGY 继续。评审以实质结论为准，实施以代码差异和独立验证为准。

`plan` 用于分析，`accept-edits` 用于已授权的实现。执行模式和提示词都不能替代权限隔离。按任务使用 Codex 的宿主权限和 AGY 的会话设置（`--settings`）。`--sandbox` 限制 AGY 执行的终端命令。严格只读时，确认文件工具和终端都受只读权限约束。禁止生产操作时，隔离生产凭据与网络访问。记录 Git 基线以保护已有未提交改动。需要隔离时，先让 Codex 在隔离工作树中开展任务，并从该工作树启动 AGY。需要命名项目时，核对其范围指向该工作树。遇到权限拒绝时，检查 stderr 和实际改动，再决定如何继续。[AGY 权限文档](https://antigravity.google/docs/permissions?tab=cli)
