# 委托 AGY 执行

在当前对话中接收需求、调整约束和交付结果。保留原始需求、全局设计与决策上下文，通过脚本调用 AGY，并根据结果安排后续工作。

## 决策权与实施权

- 负责解释需求、制定方案、决定技术方向和范围，并判断任务是否完成。遵守用户已有授权，业务目标变更由用户决定。
- AGY 负责分析现有代码、评估可行性，以及在批准方案内拆分步骤、编码、测试和局部修复。方案已明确要求的数据库或接口修改可直接实施。
- 要求 AGY 遇到方案疑问或方向冲突时报告事实、影响、建议和待决定的问题。它可以继续明确授权且不依赖该决定的部分。
- 按任务需要决定委托粒度和轮次，选择是否先做可行性分析、补充实验、修复或重规划。
- 将日常代码实现与修复委托 AGY。直接进行规划、检查和验证。AGY 不可用时明确报告，变更分工需遵循用户意愿。

## 开始一次委托

首次使用时读 [交接协议与调用方式](references/protocol.md)，运行 `command -v agy` 和 `agy --help` 检查当前版本参数。脚本依赖 Python 3 与 POSIX 系统。

先检查适用的项目规则和工作区状态。记录仓库绝对路径、当前 HEAD、暂存及未暂存改动、相关未跟踪文件。已有改动涉及本次任务时，保存足以区分前后变化的内容或补丁，保留用户原有工作。

在任务说明中直接给出目标、原始需求摘要、批准方案、验收条件、允许改动范围和必须上报的边界。只传递完成委托所需的上下文，并要求遵守适用的项目规则。可行性分析要明确要求只读，实施要明确允许的修改。

使用 `scripts/run_agy.py` 调用 AGY，给每次调用指定独立的结果目录。分析用 `--mode plan`，授权范围内的实现用 `--mode accept-edits`。运行权限仍由 CLI 与宿主环境约束。遇到权限拒绝时检查具体动作和现有授权，按需配置单次调用的窄范围权限，禁止为通过任务而绕过授权边界。

同一工作区保持单一写入者。脚本锁可阻止使用本脚本的并发调用。AGY 执行期间，避免同时修改同一工作区。锁的边界和调用示例见协议文档。

## 接收结果并决定下一步

工具返回运行中的进程标识时，继续等待并查看日志，直到调用结束或出现需要处理的阻塞。向用户报告有意义的进展。脚本将原始 stdout、stderr、进程状态和任务输入落盘，输出过长时分段读取原文件。

先读 `run.json`、`stdout.json`、`stderr.log`，再读结构化报告。检查模式降级警告及 CLI 信封中的 `denied_actions`（如有），确认本次权限与任务要求匹配。进程退出码与 CLI 的 `SUCCESS` 表示调用层状态。AGY 的 `COMPLETED` 表示本次委托的自述结果。验证代码与证据后再判定需求是否完成。

| AGY 返回 | 处理方式 |
| --- | --- |
| `COMPLETED` | 对照本次委托目标独立核查，分析任务完成后再决定是否进入实施 |
| `NEED_CLARIFICATION` | 根据原始需求解释，给出必要上下文后再次委托 |
| `DESIGN_CONFLICT` | 核实证据，决定是否调整，并在需要时更新方案 |
| `BLOCKED` | 检查环境、权限、依赖或其他障碍，处理可恢复问题并决定后续动作 |

结合原始需求和权限边界核实 AGY 的报告与建议。实现缺陷交给 AGY 修复，设计遗漏则修订方案。把解释、决定和当前进度写入下一次任务输入即可继续。默认每次独立调用，工作区保留已有改动，调用目录保留交接记录。

非零退出、超时、中断、空输出、无效 JSON、结构化字段缺失或工具被拒绝，都先检查实际工作区及日志。调用失败可能已有部分修改，重试前核实已执行的操作，避免重复副作用。重复遇到同一问题且没有新证据或进展时，改变诊断方法或报告具体阻塞。任务有用户预算时遵守预算。

## 独立验收与交付

检查相对于委托前基线的实际差异，包括新增文件、暂存改动和未暂存改动。对照原始需求核查方案本身的遗漏、改动范围和现有调用方兼容性。独立执行与改动相关的测试、构建或运行检查，区分既有失败与新引入的问题。

检查测试内容是否能覆盖验收条件，特别留意通过删除、跳过或弱化断言取得的通过结果。验收需要但无法执行的检查如实标为未验证。

在当前对话内交付改动摘要、验证证据和未解决事项，由用户做最终业务验收。长任务或上下文切换前，保留简短交接记录，包含最新决策、代码基线、最近调用目录、待处理问题和验证结论。
